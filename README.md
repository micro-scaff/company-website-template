# company-website-template

一个基于 Next.js + Go 开发的企业官网模板，采用 SSR 架构，兼顾 SEO、首屏加载性能与可扩展性，适用于企业官网、品牌官网及产品展示类网站的快速搭建。

项目按三个独立目录组织：

| 目录 | 职责 |
| --- | --- |
| `web/` | Next.js 官网，负责多语言展示、SSR、SEO 及受保护的草稿预览 |
| `admin/` | 独立后台管理前端，负责内容、语言、账号及留资管理；技术栈待初始化时确定 |
| `server/` | Go 后端服务，为官网和后台提供 API、权限校验及数据库访问 |

官网与管理后台独立开发、构建，共用后端接口契约。具体职责、路由和部署方式见 [ARCHITECTURE.md](ARCHITECTURE.md)。

| 文件                 | 主要作用                 | Codex 应该怎么用  |
| ------------------ | -------------------- | ------------ |
| `AGENTS.md`        | **Codex 总规则 / 项目入口** | 每次开发都遵守      |
| `README.md`        | 给人看的项目介绍和启动方法        | 了解项目基本信息     |
| `CURRENT-SCOPE.md` | **当前版本做什么、不做什么**     | 判断需求是否越界     |
| `ARCHITECTURE.md`  | **系统架构和技术边界**        | 做技术方案、改结构前阅读 |
| `CONVENTIONS.md`   | 编码、命名、目录、API 等规范     | 写代码时遵守       |
| `ROADMAP.md`       | 未来规划                 | 避免把未来功能提前实现  |
| `DECISIONS.md`     | 重要技术决策及原因            | 避免反复推翻已有决定   |
| `TASKS.md`         | 当前任务 / 待办            | 连续开发时跟踪进度    |
| `TESTING.md`       | 测试策略和命令              | 修改完成后进行验证    |
| `DEPLOYMENT.md`    | Docker、CI/CD、部署方式    | 涉及部署时读取      |
